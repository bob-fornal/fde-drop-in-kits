# Requirements Breakdown

Read the issue and relevant domain files without changing application code.
Produce a spec with problem and users, In Scope, Out of Scope, data model and
API impact, assumptions, dependencies and open questions. Add testable
acceptance criteria in Given/When/Then form, including failure and edge cases.
Cite evidence and ask the requester about material ambiguity instead of guessing.
